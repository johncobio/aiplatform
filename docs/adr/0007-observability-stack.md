# 0007 — Observability: Prometheus Operator stack, OpenTelemetry traces, Jaeger

2026-09-16 · Accepted

## Context

V4 needs metrics, dashboards and tracing for inference workloads on a
laptop whose Docker VM is capped at 4 GB. The stack must carry over to EKS
unchanged in shape, and the inference metrics must be the ones later phases
autoscale and alert on.

## Decision

- **kube-prometheus-stack** (Prometheus Operator, Prometheus, Grafana,
  kube-state-metrics) installed by `cluster up`, slimmed: Alertmanager and
  node-exporter off until V8; kind-incompatible control-plane scrape targets
  off; 2-day retention; explicit resource requests and limits. The
  Operator's `ServiceMonitor` CRD is the contract: the `llm-workload` chart
  emits one with `environment`, `workload` and `model` labels so dashboards
  and rules filter on platform concepts, not pod names.
- **Metrics stay Prometheus-native.** The service already exposes `llm_*`
  metrics; Prometheus scrapes them directly. Routing metrics through the
  OpenTelemetry Collector would add a hop without adding information.
- **Traces go through OpenTelemetry.** The service uses the OTel SDK with
  FastAPI auto-instrumentation and two hand-written spans (`llm.queue_wait`,
  `llm.generate`) carrying GenAI semantic-convention attributes
  (`gen_ai.request.model`, `gen_ai.usage.*`). Export is OTLP/HTTP (no grpcio)
  to an **OpenTelemetry Collector** (deployment mode) which forwards to
  **Jaeger v2 all-in-one** (in-memory). Tracing is a no-op when
  `OTEL_EXPORTER_OTLP_ENDPOINT` is unset, so tests and the `local` target pay
  nothing. Access logs carry the trace id for log↔trace correlation.
- **Dashboards as code.** `deploy/observability/dashboards/*.json` are
  generated by `scripts/gen_dashboard.py` and shipped as ConfigMaps that
  Grafana's sidecar loads. Cost panels are labelled estimates driven by a
  `node_hourly_cost` variable; nothing pretends to be a bill.

## Consequences

- The same ServiceMonitor, dashboards and OTel wiring work on EKS with the
  managed or self-hosted Prometheus of the AWS phase; only the storage and
  the trace backend (Jaeger → Tempo/X-Ray) would change.
- Memory: the stack adds roughly 900 MiB of usage on the kind node (Grafana
  with sidecars ~400 MiB, Prometheus ~370 MiB). Installing it beside Argo CD
  and the LLM workload exhausted the 3.9 GiB node and stalled the API server.
  `aiplatform cluster addon pause|resume` scales an add-on's pods to zero
  (keeping Helm releases, CRDs and desired state) so the laptop runs GitOps
  *or* observability at a time. On EKS this is a node-group sizing decision.
- The OTel Collector's metrics/logs pipelines only log to `debug` for now;
  they exist so that a future move to OTel-native metrics is a config change.
